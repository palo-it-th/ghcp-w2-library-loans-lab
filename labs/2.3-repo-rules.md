# 2.3 · Write the repo rules (8 นาที)

**สิ่งที่จะฝึก:** เขียนกติกาที่ใช้ทั้ง repo โดยยังไม่ใส่รายละเอียดการเขียน test

## ทำ

1. อ่าน [กติกาทีม](../docs/team.md) เรื่องเงิน เวลา migration และการตรวจหลังแก้โค้ด (2 นาที)
2. สร้าง `.github/copilot-instructions.md` ด้วยคำของตัวเอง (5 นาที)
   เขียนกติกา 3 เรื่องของแอป แล้วเพิ่มกฎให้รัน test ที่เกี่ยวข้องหลังแก้โค้ดอีก 1 ข้อ
   แต่ละกฎบอก **ต้องทำอะไร → เพราะอะไร → ดูโค้ดหรือรันคำสั่งไหน**
3. ตรวจรายการด้านล่าง แล้วไปต่อ (1 นาที)

ใช้โครงนี้ช่วยเขียนได้ ไฟล์กฎกลางเป็น Markdown ไม่ต้องมี frontmatter:

```markdown
# กติกาของโปรเจกต์ Library Loans

- การคำนวณเงินต้อง ... เพราะ ... ดูตัวอย่างที่ `src/money.js`
- การอ่านเวลาปัจจุบันต้อง ... เพราะ ... ดูตัวอย่างที่ `src/clock.js` และ `src/loans.js`
- migration ที่มีอยู่ห้าม ... เพราะ ... ถ้าต้องเปลี่ยนโครงสร้างฐานข้อมูล ให้เพิ่ม ... ใน `db/migrations/`
- หลังแก้ไฟล์โค้ดจริง รวมถึง comment ต้องรัน test ที่เกี่ยวข้องก่อนสรุปงาน เพราะ ...
  ถ้าแก้ `src/loans.js` ให้รัน `node --test tests/loans.test.js`
  ระบุคำสั่งสำหรับไฟล์อื่นตามกติกาทีมด้วย รายงานผลจริง ถ้ารันไม่ได้หรือไม่ผ่านให้บอกเหตุผล
  ถ้าแค่เสนอ diff โดยยังไม่ได้แก้ไฟล์ ไม่ต้องรัน test
```

เติมช่องให้เป็นกฎที่ทำตามได้จริง ไม่ใช้คำว่า “clean code” หรือ “best practice”
ประมาณ 10–20 บรรทัดก็พอ เป้าคือไม่เกินประมาณ 30 บรรทัด
นี่เป็นเป้าของ workshop ไม่ใช่ limit ของ GitHub

กฎให้รัน test หลังแก้โค้ดใช้กับทุกงาน ไม่ใช่กติกาเฉพาะการเขียน test
ยังไม่ใส่กฎตั้งชื่อ test หรือการใช้ fakeClock ใน test ที่นี่ เพราะจะทำในข้อ 2.5
และไม่ย้ายขั้นตอน “เสนอ case แล้วรอ”
จาก prompt file มาไว้ในกฎทั้ง repo
ถ้า prompt ของคุณมีกฎที่จริงทุกงานอยู่แล้ว ให้ย้ายกฎนั้นมาไว้ไฟล์นี้ ไม่คัดลอกสองที่

**เช็กก่อนทำข้อต่อไป**

- [ ] มีกฎเรื่องเงิน เวลา migration และการรัน test หลังแก้โค้ด พร้อมเหตุผลและ path หรือคำสั่งจริง
- [ ] แยกอ่านเวลาปัจจุบันออกจากการแปลงวันที่ที่ระบุไว้ได้
- [ ] ยังไม่มีรายละเอียดการตั้งชื่อ test หรือการใช้ fakeClock ใน test ปนอยู่ในกฎกลาง
