# 2.4 · Path-scoped

**เป้า:** กฎตั้งชื่อ test ไม่ต้องตามไปทุกไฟล์ เหมือนบรรณารักษ์ไม่ต้องตามกลับบ้าน

## 1. สร้างกฎ

กฎกลางในข้อ 2.2 บอกว่า **แก้โค้ดแล้วต้องรัน test**
ข้อนี้เพิ่มกฎว่า **เมื่อเขียน test ต้องเขียนอย่างไร** โดยไม่ย้ายกติกาทั้งสองเรื่องมารวมกัน

สร้าง `.github/instructions/tests.instructions.md` หรือสร้างผ่าน Ctrl+Shift+P -> Chat: New Instruction File ตั้งชื่อว่า tests:

```markdown
---
description: "Use when creating or editing *.test.js files"
applyTo: "**/*.test.js"
---

# Test conventions

- New tests MUST be grouped with `describe('functionName', ...)`, one `describe` per function under test.
- Test names inside `describe` MUST be camelCase and say the expected result, e.g. `returnsZeroWhenDaysLateIsZero`.
- Get `describe` and `test` from the harness destructuring, same as `test` and `assert`.
- Time-related tests MUST use fakeClock from src/clock.js; do not sleep or read wall-clock time.
```

`applyTo` คือ glob ใน frontmatter ที่บอกว่ากฎนี้ผูกกับไฟล์ไหน (glob นับจาก root ของ workspace):

| applyTo               | ครอบคลุม                                                 |
| --------------------- | -------------------------------------------------------- |
| `**/*.test.js`        | ไฟล์ `.test.js` ทุกที่ใน workspace (ที่เราใช้ใน lab นี้) |
| `tests/**`            | ทุกไฟล์ใต้โฟลเดอร์ `tests/`                              |
| `**/*.{test,spec}.js` | ทั้ง `.test.js` และ `.spec.js`                           |
| `**`                  | ทุกไฟล์ (เหมือน repo-wide)                               |

กฎนี้จึง apply เฉพาะไฟล์ `*.test.js` เช่น `tests/loans.test.js` ส่วน `api/status.js` ไม่ match

## 2. Edit ที่ match (3 นาที)

New Chat:

```text
เพิ่ม test หนึ่งตัวใน #tests/loans.test.js:
buildFeeReceipt สำหรับคืนตรงเวลา (0 วัน) ต้องได้ยอดศูนย์และ timestamp ตามเวลาที่ส่งเข้าไป
```

ดู References และ diff แยกกัน: test instructions มาไหม? `describe` ชื่อ test และ clock เป็นอย่างไร?
ไม่มี Node ให้ refresh `tests.html` ไฟล์เดิมเชื่อม browser runner ไว้แล้ว

## 3. Edit ที่ไม่ match (2 นาที)

New Chat:

```text
ใน #api/status.js เพิ่ม comment สั้นๆ เหนือ getStatus ว่านี่เป็น readiness
ของห้องสมุด ไม่ใช่ HTTP server ห้ามเปลี่ยน return value
ไม่ต้องเพิ่มหรือแก้ test
```

กฎกลางให้รัน test หลังแก้ API ด้วย แม้แก้แค่ comment
การรัน `tests/status.test.js` ไม่ใช่การขอให้แก้หรือเขียน test
คาดว่า repo instructions ยังมา แต่ test instructions ไม่จำเป็นกับงานนี้
ถ้ามันยังมา ให้จดตามจริง ดูว่า agent เปิด tests หรือไม่
description และ context อื่นอาจมีผล อย่าถือว่า glob อย่างเดียวอธิบายทุกอย่าง
